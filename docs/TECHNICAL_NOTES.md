# floor_inspect — บันทึกเชิงเทคนิค (Technical Notes)

> เอกสารนี้คือ **บันทึกการพัฒนาเชิงลึก**: วัดอะไร ผิดตรงไหน แก้อย่างไร พร้อมตัวเลขจากกล้องจริง
> ถ้าเพิ่งเริ่มใช้ ให้อ่าน [README หลัก](../README.md) ก่อน — ส่วนนี้ไว้สำหรับคนที่จะ
> ปรับเกณฑ์ ดีบั๊ก หรืออยากรู้ว่าทำไมโค้ดถึงเขียนแบบนั้น

## floor_inspect — ตรวจความไม่เรียบของพื้นสำหรับ AMR ด้วย RealSense D455

วัด **หลุม / เนิน / ลิ่มรอยต่อ / ความลาดเอียง** ของพื้นเป็นมิลลิเมตร แล้วตอบคำถามที่ใช้งานได้จริง:
*"หุ่นตัวนี้วิ่งผ่านบริเวณนี้ได้ไหม และต้องชะลอเหลือเท่าไร"*

ผลลัพธ์ตรงกับ deliverable ของงานสแกนพื้นโกดังจริง — แผนที่ค่าเบี่ยงเบน (เขียว=ได้ระดับ /
แดง=นูน / น้ำเงิน=ยุบ), ดัชนี **ASTM E1155 (FF/FL)**, รายการจุดที่ต้องซ่อม และ overlay
ความเสี่ยงทับภาพกล้องแบบต่อพิกเซล

## เริ่มใช้ใน 1 นาที (ยังไม่ต้องมีกล้อง)

```bash
cd ~/floor-inspect
python3 -m floor_inspect.cli demo --scene warehouse --out /tmp/fi
```

ได้ครบชุด: `overlay_risk.png` `topdown_dev.png` `profile.png` `report_figure.png` `report.md`
พร้อมบรรทัดเทียบกับเฉลยของฉากจำลอง (รู้ทันทีว่าวัดคลาดไปกี่มิลลิเมตร)

ฉากที่มีให้: `flat` (พื้นเรียบ ใช้ทดสอบ false positive) · `targets` (เป้ามาตรฐาน 3/5/10/20 mm)
· `warehouse` (ลาดเอียง + คลื่น + ลิ่มรอยต่อ + หลุมสึก)

## ใช้กับกล้องจริง

```bash
./scripts/run_floor_inspect.sh                    # balanced (ค่าเริ่มต้น)
./scripts/run_floor_inspect.sh detail             # ละเอียดสุด
./scripts/run_floor_inspect.sh smooth amr_small   # ลื่นสุด + สเปกหุ่นเล็ก
GLARE=1 ./scripts/run_floor_inspect.sh detail     # เปิด HDR สู้พื้นมันวาว

# หรือสั่งตรง ๆ
ros2 launch floor_inspect inspect.launch.py quality:=detail amr:=amr_generic
ros2 run floor_inspect inspect_node             # ถ้าเปิดกล้องไว้แล้ว
```

### โหมดภาพ — เลือกระหว่างความลื่นกับความละเอียด

ตัวเลขทั้งหมดวัดจริงบนเครื่องนี้ (สาย **USB 2.1** ซึ่งเป็นคอขวดหลัก):

| โหมด | depth | color | สตรีม | วิเคราะห์ | เล็กสุดที่เชื่อได้ | พื้นที่/เฟรม |
|---|---|---|---|---|---|---|
| `smooth`   | 640×480×30  | 640×480×30  | 30 Hz  | ~7 fps  | 3.9 mm | 2.6 m² |
| `balanced` | 848×480×10  | 1280×720×10 | 9.1 Hz | ~11 fps | 2.5 mm | 3.0 m² |
| `detail`   | 1280×720×5  | 1280×720×5  | 4.4 Hz | ~5 fps  | **1.6 mm** | 3.5 m² |

`balanced` ชนะเกือบทุกด้าน จึงเป็นค่าเริ่มต้น ใช้ `detail` ตอนจอดนิ่งแล้วกดสแกน

**อยากได้มากกว่านี้ต้องย้ายไป USB 3** — ตอนนี้กล้องต่อผ่าน USB 2.1 (480 Mbps) ทำให้
เพดานตายตัวอยู่ที่ 848×480@10 หรือ 1280×720@5 ถ้าเสียบพอร์ต USB 3 (สาย USB-C ที่มากับ
กล้อง, พอร์ตที่มีสัญลักษณ์ SS) จะได้ 848×480 ถึง **90 Hz** และ 1280×720 ที่ 30 Hz
เช็คว่าต่อแบบไหนอยู่ด้วย `rs-enumerate-devices | grep -i "usb type"`

### พื้นมันวาว / แสงสะท้อน

ค่าที่ถูกไม่มีสูตรตายตัว ขึ้นกับผิวพื้นและมุมไฟของหน้างาน จึงมีตัวกวาดหาให้:

```bash
python3 -m floor_inspect.tune_camera           # กวาดแล้วรายงาน
python3 -m floor_inspect.tune_camera --apply   # กวาดแล้วตั้งค่าที่ดีที่สุดค้างไว้
```

มันจะไล่ `laser_power`, เพดานเวลาเปิดหน้ากล้อง และ HDR แล้ววัดผลจริงสามอย่างต่อค่า:
`fill` (สัดส่วนพิกเซลที่ได้ depth — แสงสะท้อนทำให้เป็นรู), `rms`, `noise`

ปรับเองสด ๆ ก็ได้:

```bash
ros2 param set /camera/camera depth_module.laser_power 90.0      # ลดถ้าจุดสะท้อนบานเป็นรู
ros2 param set /camera/camera depth_module.hdr_enabled true      # สลับสองค่าแสงแล้วรวม
ros2 param set /camera/camera hdr_merge.enable true
ros2 param set /camera/camera depth_module.auto_exposure_limit 8000
```

ค่าที่ตั้งให้อัตโนมัติตอนเปิดระบบ (ยิงผ่าน service เพราะ `rs_launch.py` ไม่รับเป็น launch arg):

| ค่า | ตั้งเป็น | เหตุผล |
|---|---|---|
| `rgb_camera.power_line_frequency` | 1 (50 Hz) | ไทยใช้ไฟ 50 Hz — ถ้าปล่อย auto จะได้แถบมืด-สว่างไหลใต้หลอดฟลูออเรสเซนต์ |
| `rgb_camera.auto_exposure_priority` | false | ห้าม AE ยืดเวลาเปิดหน้ากล้องจนเฟรมเรตตกและภาพเบลอตอนหุ่นวิ่ง |
| `depth_module.auto_exposure_limit` | 20000 µs | จุดสะท้อนสว่างจ้าจะไม่ทำให้ AE ไล่ตามจนภาพลึกบานเป็นรู |
| `depth_module.laser_power` | 150 | ค่ากลาง ปรับด้วย `tune_camera` ตามผิวพื้นจริง |

**สิ่งที่ปรับไม่ได้:** D455 เป็นเลนส์โฟกัสตายตัว ไม่มี auto focus ให้ปรับ (ไม่มี
พารามิเตอร์ `focus` ในไดรเวอร์) — แต่ไม่กระทบการวัด เพราะความลึกมาจากกล้องคู่ IR
ไม่ได้มาจากความคมของภาพสี ระยะ 0.4–3 m อยู่ในระยะชัดลึกของเลนส์อยู่แล้ว

**ตัวช่วยที่ได้ผลที่สุดกับพื้นมันวาวคือมุมกล้อง** ไม่ใช่พารามิเตอร์: ถ้าไฟอยู่ในตำแหน่งที่
สะท้อนเข้าเลนส์พอดี ให้ขยับมุมก้มหรือหมุนหุ่นสักหน่อย จุดสะท้อนจะเลื่อนออกทันที

## หลักการที่ใช้ (และกับดักที่หลบไว้แล้ว)

```
depth ──▶ point cloud ──▶ ระนาบอ้างอิง (RANSAC + trimmed refit)
      ──▶ floor frame (z = ค่าเบี่ยงเบนโดยตรง)
      ──▶ DEM กริด 10 mm เก็บ median ต่อเซลล์
      ──▶ ฐานอ้างอิงเฉพาะที่ ──▶ หลุม/เนิน/ลิ่ม ──▶ ความเสี่ยงต่อล้อจริง
```

สี่จุดที่ทำให้ผลเชื่อถือได้ (ทุกข้อมี regression test คุมไว้ใน `test/`):

1. **ระนาบอ้างอิงต้องไม่โดนหลุมดึง** — RANSAC threshold 20 mm ยังนับหลุม 5 mm เป็น inlier
   และทำระนาบเอียงพอจะเพี้ยนหลายมิลลิเมตรที่ปลายกริด จึง refine ด้วย trimmed least-squares
   ตัด outlier ด้วย MAD ซ้ำหลายรอบ

2. **threshold ต้องปรับตาม noise จริงของแต่ละจุด** — ที่ 0.5 m noise ต่อจุด ~0.5 mm แต่ที่ 1.8 m
   เกิน 6 mm ถ้าใช้ threshold เดียวทั้งภาพจะได้ false positive ที่ระยะไกลเป็นร้อยจุด
   (ทดสอบแล้วเจอ 200 จุด) ระบบจึงวัด noise จากข้อมูลเองแล้วตั้งเกณฑ์เป็น `max(ค่าคงที่, 4σ)`

3. **ฐานอ้างอิงเฉพาะที่ต้องมาจากพื้นดีเท่านั้น** — top-hat ล้วน ๆ พังสองแบบ: ฐานแบบ
   `(opening+closing)/2` ทำให้ความลึกเหลือครึ่งเดียว และเมื่อหลุมสองใบอยู่ใกล้กว่าขนาด
   structuring element จะเกิด "เนินปลอม" ตรงพื้นดีระหว่างหลุม แก้ด้วยการหาฐานสองรอบ:
   หาผู้ต้องสงสัยก่อน แล้วเฉลี่ยเฉพาะเซลล์ที่ไม่ต้องสงสัย

4. **มิลลิเมตรอย่างเดียวตัดสินไม่ได้ ต้องดูความกว้าง** — ร่องกว้าง 5 mm ลึก 50 mm ล้อ Ø150
   ข้ามฉิว ๆ แต่แอ่งกว้าง 300 mm ลึก 15 mm ล้อจมเต็ม จึงคิดจากเรขาคณิตล้อจริง
   `δ = R − √(R² − (w/2)²)`

## ขอบเขตที่ระบบยอมรับตรง ๆ

- **FL (Levelness) ต้องมีเส้นวัดยาว ≥ 3.048 m** ตามมาตรฐาน กล้องตัวเดียวเห็นแค่ ~2 m
  ระบบจึงคืน `None` พร้อมเหตุผล แทนที่จะเดาตัวเลขออกมา — ถ้าต้องการ FL จริงต้องต่อภาพหลายจุด
- **บริเวณที่ไม่มีข้อมูล depth ≠ พื้นเรียบ** รายงานแยกเป็นชนิด `missing` เสมอ
  (หลุมลึก ผิวสะท้อน ท่อระบายน้ำ ล้วนทำให้ stereo อ่านไม่ได้)
- **ความผิดปกติที่กว้างกว่า `base_win_m` (0.40 m)** จะไปโผล่ในแผนที่ระดับรวม ไม่ใช่แผนที่ flatness
  — ตรงตามนิยาม FF vs FL ของ ASTM ไม่ใช่ข้อบกพร่อง
- **ถ้าระนาบที่จับได้ไม่เรียบพอ** (rms > 12 mm) ระบบจะบอกว่า "ยังไม่ได้เล็งพื้น"
  แทนที่จะพ่นรายการหลุมปลอมออกมา
- **สำรวจได้ < 0.15 m²** ก็ปฏิเสธเช่นกัน — ผิวเรียบผืนจิ๋วใกล้เลนส์ผ่านเกณฑ์ rms ได้
  แล้วระบบจะบอกว่า "ตรวจแล้วไม่พบอะไร" ทั้งที่แทบไม่ได้ตรวจอะไรเลย

## พื้นที่มีเนื้อผิว (พรม กระเบื้องมีลาย คอนกรีตขัดหยาบ)

เกณฑ์ตายตัวใช้ไม่ได้กับพื้นพวกนี้ บนพรมจริงระบบเคยรายงาน **176 จุดในเฟรมเดียว**
เพราะขนพรมกับรอยต่อแผ่นสั่นเกิน 4 mm อยู่แล้ว — ซึ่งล้อกลิ้งข้ามไปไม่รู้สึกอะไร

ระบบจึงวัด **"เนื้อผิว"** ของพื้นเองแล้วยกเกณฑ์ตาม:

```
เกณฑ์ต่อเซลล์ = max( ค่าคงที่ 4 mm , 4 × noise เซนเซอร์ , 2.5 × เนื้อผิวตรงนั้น )
```

เนื้อผิวหาโดย fit `rough(ระยะ) = a + b·ระยะ²` เข้ากับเปอร์เซ็นไทล์ที่ 25 ของความขรุขระ
ที่วัดได้ในแต่ละชั้นระยะ — `a` คือเนื้อผิวของวัสดุ `b·ระยะ²` คือ noise ของ stereo ที่โต
ตามระยะกำลังสอง ที่ต้องใช้เปอร์เซ็นไทล์ 25 ต่อชั้น (ไม่ใช่ค่าท้องถิ่นตรง ๆ) เพราะเป้ากลม
Ø120 mm กินพื้นที่ครึ่งหนึ่งของหน้าต่างวัด แล้วจะ "ยกเกณฑ์ของตัวเอง" จนหายไปหมด

วัดจริงบนพรมเทา (กล้องสูง 0.92 m):

| ระยะ | เนื้อผิวที่วัดได้ | เกณฑ์ที่ใช้ |
|---|---|---|
| 0.97 m | 4.2 mm | 10 mm |
| 1.37 m | 8.4 mm | 21 mm |
| 2.04 m | 18.5 mm | 46 mm |

ผล: **176 จุด → 39 จุด** และที่เหลือคือของจริงล้วน (สายไฟ ปลั๊กพ่วง อะแดปเตอร์ ขาโต๊ะ ผนัง)

สิ่งที่ต้องรู้: **บนพรม ที่ระยะ 1 m กล้องแยกหลุม 4 mm ไม่ออกจริง ๆ** ระบบจึงรายงาน
`เล็กสุดที่เชื่อได้` สูงขึ้นตามไปด้วย ถ้าต้องการความไวเต็มที่ ต้องลดความสูงกล้องและ
มองใกล้ขึ้น (ที่ระยะ 0.5 m เนื้อผิวเหลือ ~1 mm เกณฑ์กลับมาที่ 4 mm)

ปรับความเข้มได้ด้วย `k_rough` (ยิ่งสูงยิ่งกรองแรง):

```bash
ros2 param set /floor_inspect k_rough 3.0    # พรมหยาบมาก
ros2 param set /floor_inspect k_rough 1.5    # พื้นอีพ็อกซี/คอนกรีตขัดมัน
```

### ตัดบริเวณที่ "วัดไม่ได้แล้ว" ออกเอง

พอเกณฑ์โตตามระยะ ก็มีจุดหนึ่งที่เกณฑ์ใหญ่เกินกว่าหลุมที่สนใจ — ตรงนั้นไม่ใช่
"พื้นเรียบ" แต่คือ "มองไม่เห็นแล้ว" ระบบจะตัดออกจากพื้นที่สำรวจให้เอง (`max_usable_mm`
ค่าเริ่มต้น 15 mm) และเอาเฉพาะก้อนที่ต่อเนื่องกับหน้าหุ่น

ผลกับพรมผืนเดิม กล้องสูง 0.92 m:

| | ก่อน | หลัง |
|---|---|---|
| จุดที่รายงาน | 161 | **3** |
| พื้นที่ที่อ้างว่าสำรวจ | 3.17 m² | 0.70 m² (เท่าที่วัดได้จริง) |
| เล็กสุดที่เชื่อได้ | 25 mm | 11 mm |

ตัวเลขพื้นที่ลดลงเพราะเลิกนับบริเวณที่วัดไม่ได้ ไม่ใช่เพราะเห็นน้อยลง

```bash
ros2 param set /floor_inspect max_usable_mm 8.0    # เข้มขึ้น เอาเฉพาะที่แม่นจริง
ros2 param set /floor_inspect max_usable_mm 30.0   # ผ่อน เอาไว้ดูภาพรวมกว้าง ๆ
```

## ความนิ่งของผลลัพธ์

ระบบ fit ค่าใหม่ทุกเฟรม ถ้าไม่ระวังจะได้ผลที่เด้งไปมาทั้งที่ฉากไม่ขยับ วัดจริงตอนยังไม่แก้
(กล้องนิ่ง ฉากนิ่ง 20 เฟรมติด):

| ค่า | ก่อนแก้ (sd) | หลังแก้ (sd) |
|---|---|---|
| `plane_rms_mm` | 0.08 | 0.04 |
| `fill` | 0.00 | 0.00 |
| **`area_m2`** | **0.72** (0.08–3.51) | **0.06** (1.06–1.31) |
| **`rough_mm`** | **5.79** (4.0–31.6) | **0.13** (3.6–4.2) |
| **`detectable_mm`** | **11.96** (10–68) | **0.40** (10.9–12.4) |
| **`n_defects`** | **5.78** (0–26) | **1.38** (2–7) |

สังเกตว่าข้อมูลจากกล้องนิ่งอยู่แล้ว (`fill` sd 0.00) — ความแกว่งทั้งหมดมาจากการคำนวณ
สาเหตุมี 6 อย่าง แก้แยกกัน:

1. **แบ่งชั้นระยะด้วยช่วงเท่า ๆ กัน** — เซลล์ไกลไม่กี่เซลล์ยืดช่วงจนชั้นท้ายแทบว่าง
   แล้ว fit เอียงตามมันทั้งเส้น → เปลี่ยนไปแบ่งด้วยควอนไทล์ + ต้องมี ≥200 เซลล์ต่อชั้น
2. **fit ใหม่หมดทุกเฟรมโดยไม่มองเฟรมก่อน** → EMA ค่าสัมประสิทธิ์ `(a, b)` ข้ามเฟรม
   (`texture_alpha`, ค่าเริ่มต้น 0.30) พร้อมขอบเขตความเป็นไปได้ทางกายภาพ
3. **`usable_mask` ยึดแถวล่างสุดของ DEM เป็นสมอ** — เฟรมไหนแถวล่างหลุดเกณฑ์
   พื้นที่จะหล่นจาก 3.5 m² เหลือ 0.08 m² ทันที → เปลี่ยนเป็นเก็บก้อนใหญ่สุด + ก้อนที่
   ใหญ่เกิน 25% ของมัน
4. **จุดที่ค่าอยู่ตรงเส้นเกณฑ์พอดีสลับเข้า-ออกทุกเฟรม** → ต้องโผล่ซ้ำ 2 ใน 3 เฟรมถึงรายงาน
   (`confirm_hits`/`confirm_frames`) จับคู่ด้วยตำแหน่งในรัศมี 10 cm
   ถ้ากล้องขยับเกิน 2 cm หรือมุมก้มเปลี่ยนเกิน 3° จะล้างประวัติเอง — ตอนหุ่นวิ่งจึงกลับไป
   รายงานทุกเฟรมอัตโนมัติ สิ่งกีดขวางกับรูข้อมูลไม่ต้องรอยืนยัน (พลาดแล้วอันตรายกว่า)

5. **ขอบกริด DEM ขยับตามพิกเซลไกลสุดที่บังเอิญคืน depth มา** — วัดจริง 12 เฟรมติดกัน
   ได้ `x_max` เลื่อน 1.454–1.465 m (11 mm) กับ `y_max` เลื่อน 17 mm ทั้งที่กล้องกับพื้น
   ไม่ขยับเลย แปลว่าทุกเซลล์ถูกสุ่มตัวอย่างคนละเฟสทุกเฟรม → ล็อกขอบให้ตกบนพิกัดโลก
   ที่หารด้วย `cell` ลงตัวเสมอ (`build_dem`) เซลล์เดิมจึงกินพื้นที่จริงชุดเดิมทุกเฟรม
6. **เซลล์ที่มีจุด depth น้อยเกินไปถูกเชื่อเท่าเซลล์ที่ข้อมูลแน่น** — สาเหตุใหญ่ที่สุด
   ของจุดปลอมที่ระยะไกล ดูหัวข้อถัดไป

```bash
ros2 param set /floor_inspect confirm_hits 1     # ปิดการยืนยัน (ตอบไวสุด)
ros2 param set /floor_inspect confirm_frames 3   # เริ่มต้น 5/3 — ลดลงถ้าอยากตอบไวขึ้น
ros2 param set /floor_inspect confirm_hits 2
```

### เซลล์ข้อมูลบาง = แหล่งจุดปลอมที่ระยะไกล (`min_points_cell`)

จำนวนจุด depth ที่ตกในเซลล์หนึ่งลดลงเร็วมากตามระยะและมุมเฉียง (`sin(มุมตกกระทบ)/ระยะ²`)
วัดจากพรมจริง 12 เฟรม กล้องสูง 0.88 m เซลล์ 10 mm:

| มุมตกกระทบ | ระยะ | จุด/เซลล์ | ผลที่ได้ |
|---|---|---|---|
| 63° | 0.95 m | 14 | เนินจริง +24 mm เจอครบ 12/12 เฟรม สูงคงที่ (sd 2.5 mm) |
| 44° | 1.26 m | 6 | เจอบ้างไม่เจอบ้าง แต่ค่าที่ได้ตรงกัน |
| 29–35° | 1.5–1.9 m | **2–5** | **หลุมผี −37 mm / เนินผี +26 mm โผล่ ๆ หาย ๆ** |

`median` ของ 2–4 จุดกรอง outlier ไม่ได้เลย และ noise ของ stereo สัมพันธ์กันเชิงพื้นที่
(block matching หน้าต่าง ~7 px) ทั้งหย่อมจึงพลาดไปทางเดียวกันหมด — กลายเป็นหลุมทั้งใบ
ที่ตัวประมาณ noise/ความขรุขระมองไม่เห็น เพราะ "ผิวปลอม" นั้นเรียบในตัวมันเอง

ระบบจึงตัดบริเวณที่จุดต่อเซลล์ต่ำกว่า `min_points_cell` (เริ่มต้น **6**) ออกจากพื้นที่สำรวจ
ผลที่วัดได้บนพรมชุดเดิม:

| | จุดปลอมไกล/เฟรม | sd ของ `n_defects` | พื้นที่ | `detectable_mm` |
|---|---|---|---|---|
| ปิด (0) | 1.75 | 2.18 | 1.72 m² | 10.4 |
| **6 (เริ่มต้น)** | **0.00** | **1.25** | 1.31 m² | 9.5 |
| 8 | 0.00 | 0.83 | 0.93 m² | 9.0 |

(เคยลองตัดด้วย "มุมตกกระทบ < 40°" แทน ได้พื้นที่แค่ 0.98 m² และยังมีจุดปลอมเหลือ —
ความหนาแน่นจุดเป็นตัวแปรที่ตรงกว่า เพราะมันรวมระยะ มุม ความละเอียด `pixel_stride`
และขนาด `cell` ไว้ในตัวเดียวแล้ว)

**`pixel_stride` กับ `cell` ต้องไปด้วยกัน:** stride 2 ทำให้จุดต่อเซลล์เหลือ 1/4
ที่ 848×480 + เซลล์ 10 mm เหลือ ~3 จุด/เซลล์ ระบบจะตัดจนพื้นที่เหลือ 0.42 m²
ขยับเป็นเซลล์ 15 mm ได้ 1.00 m² และ 20 mm ได้ 1.69 m²

```bash
ros2 param set /floor_inspect min_points_cell 0.0    # ปิด (ได้พื้นที่มากขึ้น จุดปลอมกลับมา)
ros2 param set /floor_inspect min_points_cell 8.0    # เข้มขึ้น
```

นอกจากนี้ยังมีด่านเชิงฟิสิกส์ของล้อ: ร่องที่แคบกว่าล้อจะถูกคร่อมข้าม ล้อจมได้แค่
`δ = R − √(R² − (w/2)²)` — ร่องกว้าง 20 mm ใต้ล้อ Ø75 ล้อจมได้ 1.35 mm เท่านั้น
ไม่ว่าจะลึกแค่ไหน จึงไม่นับเป็น defect (`min_effective_mm` ค่าเริ่มต้น 2.0 mm)
ไม่ใช้กับ `step` เพราะลิ่มขอบคมแคบ ๆ กระแทกล้อได้จริง

## ตอนหุ่นวิ่ง: ต้องชดเชยการเลื่อนก่อนยืนยันผล (`motion_compensate`)

พิกัด `(x, y)` ของ defect วัดจาก **ตีนตั้งฉากของกล้องบนพื้น** ไม่ใช่จากพิกัดโลก
(`surface_core.floor_transform` → `origin = -plane.d * plane.n`) พอหุ่นวิ่ง
หลุมเดิมบนพื้นจึงได้พิกัดใหม่ทุกเฟรม ถ้าเอาไปจับคู่กับประวัติตรง ๆ จะไม่มีวันตรงกัน
แล้วตัวยืนยัน (`confirm_hits`) จะ **กลบของจริงทิ้งทั้งหมด**

ด่านเดิมที่ล้างประวัติเมื่อ "ความสูง/มุมก้มเปลี่ยน" ไม่ช่วยเลย เพราะวิ่งตรงบนพื้นราบ
ทั้งสองค่าไม่เปลี่ยน วัดจริงด้วยการเรียก `_confirm` ตัวจริง (หลุมจริง 1 จุด กล้องวิ่งเข้าหา):

| ความเร็ว | เลื่อน/เฟรม @3.4 fps | ก่อนแก้ | หลังแก้ |
|---|---|---|---|
| อยู่กับที่ | 0 cm | 14/14 | 14/14 |
| 0.2 m/s | 5.9 cm | **2/14** | 14/14 |
| 0.3 m/s | 8.8 cm | **2/14** | 14/14 |
| 0.5 m/s | 14.7 cm | **2/8** | 8/8 |

ทิศของความผิดพลาดคือทิศที่แย่ที่สุด: ของจริงหายเงียบ ๆ (ไม่ใช่ของปลอมโผล่)
และหายเฉพาะตอนหุ่นทำงานจริง ซึ่งเป็นสภาพเดียวที่ระบบนี้มีไว้ใช้

`_scene_shift()` วัดว่าพื้นเลื่อนไปกี่เมตรระหว่างสองเฟรม ด้วย phase correlation
บนกริด DEM แล้วเลื่อนประวัติตามมาให้อยู่เฟรมเดียวกันก่อนจับคู่ ใช้ DEM ไม่ใช่ IMU
เพราะ accel อย่างเดียวหาระยะเลื่อนไม่ได้ (ต้องอินทิเกรตสองชั้น ดริฟต์ทันที)
**ถ้าวันหนึ่งหุ่นมี `/odom` ให้ใช้ค่านั้นแทน แล้วเหลือตัวนี้เป็นตัวสำรอง** — จะแม่นกว่ามาก

### เกณฑ์ความมั่นใจ: ทำไมต้องเป็น NCC ไม่ใช่ response ของ phase correlation

ค่าที่วัดผิดอันตรายกว่าค่าที่วัดไม่ได้ — เลื่อนประวัติไปผิดที่ครึ่งเมตรแล้วจับคู่ไม่เจอ
ก็กลบของจริงเหมือนเดิม จึงต้องมีด่านคัด

**ด่านแรกที่ลองแล้วผิด:** ใช้ค่า `response` ที่ `cv2.phaseCorrelate` คืนมา
กวาดข้อมูลจากตัวจำลอง 162 ตัวอย่างแล้วได้เกณฑ์ 0.70 (err สูงสุด 18 mm) ดูดีมาก
จนเอาไปลองกับกล้องจริง:

| | เฟรมที่วัดถูก | ผ่านเกณฑ์ 0.70 |
|---|---|---|
| ตัวจำลอง | `resp` 1.03–1.14 | ผ่าน |
| **กล้องจริง (พรม, cell 10 mm)** | `resp` **0.36–0.79** | **0/9 เฟรม** |

`resp` ไม่ได้ normalize จึงขึ้นกับสถิติของลายพื้น เทียบข้ามอุปกรณ์ไม่ได้เลย
เกณฑ์ที่คัดมาอย่างดีจากตัวจำลองจึง **ปิดการชดเชยเงียบ ๆ บนฮาร์ดแวร์จริง**
ทั้งที่ค่าที่วัดได้แม่นระดับ 2 mm — เป็นบั๊กที่เทสต์ในตัวจำลองจับไม่ได้เลย

**ด่านที่ใช้จริง:** เลิกเชื่อค่าความมั่นใจ แล้วตรวจตรง ๆ ว่า *เลื่อนตามที่วัดแล้ว
สองกริดทับกันจริงไหม* ด้วย NCC ซึ่ง normalize ด้วยความแปรปรวนของสัญญาณเอง
วัดจากกล้องจริง 9 คู่เฟรม:

| กรณี | NCC | `resp` |
|---|---|---|
| วัดถูก (err ≤ 2.7 mm) | **0.67–0.86** | 0.36–0.79 |
| วัดผิด (err 526–598 mm) | **≤ 0.00** | 0.02–0.18 |
| เลื่อนผิดตั้งใจ 15 เซลล์ | **0.02–0.13** | — |

แยกขาดโดยไม่มีช่วงทับกัน ตั้ง `SHIFT_MIN_NCC = 0.45` ให้ห่างจากทั้งสองฝั่ง
ยืนยันซ้ำกับกล้องจริง 13 เฟรม (กล้องนิ่ง ความจริง = 0 mm):

```
รับ 12 เฟรม   |dx| กลาง 1.6 mm  สูงสุด 4.5 mm   |dy| สูงสุด 6.3 mm
ปฏิเสธ 1 เฟรม  dx +414 mm  dy -609 mm            <- ของที่ต้องปฏิเสธ
```

ราคาของการปฏิเสธคือ "ล้างประวัติแล้วรายงานทุกเฟรม" = ภาพกะพริบ
ราคาของการรับค่าผิดคือกลบของจริง — คนละชั้นกัน จึงเลือกทางที่พังแล้วเห็น

```bash
ros2 param set /floor_inspect motion_compensate false   # ปิด (กล้องอยู่กับที่แน่นอนเท่านั้น)
ros2 param set /floor_inspect confirm_hits 1            # ปิดตัวยืนยันไปเลย รายงานทุกเฟรม
```

> **fps มีผลโดยตรงกับเรื่องนี้** ที่ 3.4 fps (USB2) หุ่น 0.3 m/s เลื่อน 8.8 cm/เฟรม
> ซึ่งเกิน `confirm_radius_m` ที่ 30 fps (USB3) เลื่อนแค่ 1.0 cm — อยู่ในระยะสบาย ๆ
> เสียบกล้องกับพอร์ต USB3 จึงไม่ใช่แค่เรื่องความลื่น แต่ทำให้การติดตามข้ามเฟรมง่ายขึ้นด้วย

> **ข้อจำกัดที่ยังเหลือ** ตารางเปรียบเทียบ "ก่อน/หลังแก้" ข้างบนมาจากตัวจำลอง
> เพราะยังไม่มีทางเลื่อนกล้องจริงเป็นระยะที่รู้ค่าได้ ส่วนที่ยืนยันกับกล้องจริงแล้วคือ
> ความแม่นของ `_scene_shift` ตอนกล้องนิ่ง และการคัดเฟรมเสียของ NCC
> **ต้องวัดซ้ำตอนมีหุ่นวิ่งจริง**

## อ่านภาพให้ออกเมื่อพื้นมีของวางเยอะ (`max_labels`)

พื้นจริงที่มีสายไฟ/อะแดปเตอร์/ขอบเคสวางอยู่ ให้ผลได้ 30–40 จุดต่อเฟรม ซึ่ง**แต่ละจุด
ถูกต้อง** แต่ถ้าเขียนป้ายครบทุกจุด ป้ายจะทับกันจนอ่านไม่ออกและดูเหมือน "ตรวจมั่ว"
ทั้งที่ไม่ได้มั่ว

ทั้งภาพทับสีและแผนที่มองจากบนจึงเขียนป้ายเฉพาะจุดเสี่ยงสูงสุด `max_labels` จุด
(เริ่มต้น 8) เรียงตาม `risk_score` และข้ามป้ายที่จะไปทับป้ายที่วางไปแล้ว
ที่เหลือขึ้นกากบาท/กรอบอย่างเดียว แล้วสรุปมุมภาพว่า "+ อีก N จุด"
รายการเต็มยังอยู่ในตาราง `defects` ของหน้าเว็บกับ `/state.json` ครบเหมือนเดิม

```bash
ros2 param set /floor_inspect max_labels 0     # ไม่เขียนป้ายเลย เหลือแต่สี
ros2 param set /floor_inspect max_labels 20    # เขียนเยอะขึ้น
```

**วิธีตัดสินว่า "มั่ว" จริงไหม:** ดูแผนที่มองจากบน (แท็บที่สอง) แทนภาพทับสี —
มันวาดจาก DEM ล้วน ไม่มีภาพสีมากวน ถ้าพื้นส่วนใหญ่เป็นสีเขียวโดยมีแดงกระจุกอยู่
ตรงที่มีของวางจริง แปลว่าเรขาคณิตถูก ไม่ใช่การตรวจมั่ว

## พรม: "หลุมผี" ที่เฉลี่ยกี่เฟรมก็ไม่หาย (`CARPET=1`)

บนพรมที่**เรียบจริง ไม่มีหลุมเลย** ระบบรายงานหลุมเฉลี่ย **18.3 จุดต่อเฟรม**
ทั้งหมดเป็นของปลอม ไล่หาสาเหตุด้วยการวัด ไม่ใช่การเดา:

| สมมติฐาน | วิธีตรวจ | ผล |
|---|---|---|
| พรมสีไม่เสมอทำให้ depth เพี้ยน | ความสว่างตรงหลุม vs รอบ ๆ | 127 vs 128 — **ตกไป** |
| เป็น "เงา" ของเนินที่ฐานเฉพาะที่คำนวณผิด | เทียบ `dev_plane` ซึ่งไม่ผ่านฐาน | −8.2 mm ผิวยุบในข้อมูลจริง — **ตกไป** |
| ข้อมูลบางตรงนั้น | จุด depth ต่อเซลล์ | 15.1 vs 15.7 — **ตกไป** |
| เกณฑ์ไม่ปรับตามระยะ | เทียบเกณฑ์กับการกระจายจริงทีละช่วงระยะ | อัตราส่วนคงที่ 0.30–0.36 — **ตกไป** |

### สาเหตุจริง: หางหนาของ stereo ที่เกิดซ้ำที่เดิม

บนพื้นเปล่า ๆ (ตัดบริเวณที่มีของวางออกแล้ว 10 เฟรม):

```
MAD (การกระจายปกติ)   2.85 mm
p0.2 / p99.8         -12.5 mm / +11.3 mm     = 4.4x / 3.9x MAD
เกณฑ์ที่ใช้อยู่          8-13 mm              <- นั่งอยู่กลางหางพอดี
```

ถ้า noise เป็นแบบปกติ เกณฑ์ 2.85σ ควรปล่อยหลุดราว 0.2% ของเซลล์ แต่วัดได้ **9.3%**
ในช่วง 1.1–1.4 m — การกระจายมีหางหนา ซึ่ง MAD มองไม่เห็นตามนิยาม (มันคือตัวประมาณ
แบบทนทาน หน้าที่ของมันคือเมินหาง)

**หางนี้เกิดซ้ำที่เดิมทุกเฟรม ไม่ใช่ noise สุ่ม** พิสูจน์ด้วยโหมดสะสม:

| | หลุมปลอม | MAD | p99 ของ \|dev\| |
|---|---|---|---|
| 1 เฟรม | 18.1 | 3.39 mm | 20.9 mm |
| สะสม 10 เฟรม | **32** | **2.88 mm** ↓ | **60.2 mm** ↑ |

เฉลี่ยหลายเฟรมลด noise ปกติได้จริง แต่หางกลับโตขึ้น 3 เท่าและจำนวนหลุมปลอมเพิ่มขึ้น
— เพราะพื้นหลังเงียบลงแล้วความผิดพลาดที่นิ่งอยู่แล้วยิ่งเด่น **การสแกนนาน ๆ ไม่ช่วย**
`min_snr` ก็ไม่ช่วย (17.4–18.1 ที่ 4/5/6) ยืนยันว่าหย่อมพวกนี้คมชัดในข้อมูล

### ทางแก้: ยกเกณฑ์ "หลุม" อย่างเดียว

กวาดบนเฟรมจริง 10 เฟรม — "เนินจริง" นับเฉพาะที่สูง ≥ 25 mm (สายไฟม้วน/อะแดปเตอร์
ที่ยืนยันด้วยตาว่าเป็นของวางจริง):

| ค่า | หลุมปลอม | เนินจริง | พื้นที่ m² | เห็นได้ mm |
|---|---|---|---|---|
| `pothole_mm=4` (เดิม) | 18.4 | 4.1 | 2.97 | 9.5 |
| `pothole_mm=16` | 6.2 | 3.9 | 2.95 | 9.5 |
| **`pothole_mm=20`** | **2.1** | **4.1** | **2.96** | **9.5** |
| `pothole_mm=25` | 0.5 | 4.1 | 2.96 | 9.5 |
| `k_rough=5` | 0.5 | **0.1** ✗ | **1.33** ✗ | 6.8 |
| `min_defect_area_m2=0.008` | 1.3 | **1.3** ✗ | 2.96 | 9.5 |
| `dem_max_x=1.3` | 13.5 | **1.9** ✗ | **2.45** ✗ | 8.1 |

`pothole_mm` คุมเฉพาะหลุม จึงลบของปลอมได้ 89% โดยไม่แตะเนิน ไม่เสียพื้นที่สำรวจ
และไม่เสียความละเอียด ส่วนตัวอื่นลบของจริงทิ้งไปด้วยทั้งหมด

ค่า 20 มาจากหางที่วัดได้ (12.5 mm) บวกระยะเผื่อ ไม่ใช่ค่าที่ปรับให้ภาพดูสวย

```bash
CARPET=1 ./scripts/run_floor_inspect.sh detail      # หลุม 20 mm, เนิน 4 mm
POTHOLE=15 BUMP=8 ./scripts/run_floor_inspect.sh    # ตั้งเองทีละค่า
ros2 param set /floor_inspect pothole_mm 20.0   # ปรับสด ไม่ต้องรีสตาร์ต
```

> **ราคาที่ต้องจ่าย พูดตรง ๆ:** หลุมจริงลึกต่ำกว่า 20 mm บนพรมจะถูกมองข้าม
> ไม่ใช่เพราะยอมหลับตา แต่เพราะที่ระยะ 1–2 m บนพรม กล้องตัวนี้**แยกหลุมจริง 15 mm
> ออกจากหางความผิดพลาดของตัวเองไม่ได้** ถ้าต้องการความไวกว่านี้ ต้องลดระยะ
> (ที่ 0.8–1.1 m การกระจายเหลือ 1.91 mm เทียบกับ 4.33 mm ที่ 1.7–2.0 m)
> ไม่ใช่ลดเกณฑ์

> **ที่ลองแล้วพบว่าไม่มีเหตุผลรองรับ:** ตั้งเกณฑ์หลุมสูงกว่าเกณฑ์เนินโดยอ้างว่า
> ความผิดพลาดเอียงไปทางลบ — วัดแล้วหางเอียงแค่ 1.11–1.22 เท่า เกือบสมมาตร
> จึงไม่ได้สร้างกลไกนั้น ที่ต้องยกเฉพาะเกณฑ์หลุมเป็นเพราะ *ของที่วางบนพื้นเป็นเนิน
> ทั้งหมดและสูงกว่าเกณฑ์มาก* ไม่ใช่เพราะความผิดพลาดเอียง

## ของที่วางบนพื้น: วัดความสูงจากพื้น ไม่ใช่จากฐานเฉพาะที่

กล่องสูงจริง ~35 cm เคยถูกรายงานเป็น **71–112 mm และเด้งไปมา** ทั้งที่ข้อมูล
มีความสูงที่ถูกต้องนิ่งอยู่แล้ว วัด 8 เฟรมติด:

| | ค่าที่รายงาน | ความสูงเหนือระนาบพื้น (`dev_plane`) |
|---|---|---|
| 8 เฟรม | 71, 72, 72, 74, 75, 80, **112**, 74 mm | 354, 356, 354, 353, 354, 355, 355, 355 mm |
| sd | 13 mm | **1 mm** |

สาเหตุ: `peak_mm` วัดจาก `dev_local` ซึ่งเทียบกับ **ฐานเฉพาะที่** (`base_win_m`
0.4 m) ฐานนั้นปีนขึ้นไปอยู่บนตัวของเองเมื่อของกว้างใกล้ขนาดหน้าต่าง ความสูงจึงยุบ
และแกว่งตามว่าเฟรมนั้นฐานปีนขึ้นไปมากแค่ไหน

อาการที่สอง จากรากเดียวกัน: กล่อง**ใบเดียวถูกซอยเป็นหลายก้อนคนละชนิด** เพราะ
ตรงกลางกล่อง `dev_local` ยุบเกือบศูนย์ (ต่ำกว่า `obstacle_mm`) แต่ขอบยังสูง —
วัดจริงเฟรมหนึ่งได้ `obstacle 75 + obstacle 74 + bump 56 + bump 51` จากกล่องใบเดียว

**แยกแนวคิดให้ชัด:**

| | คืออะไร | วัดเทียบกับ |
|---|---|---|
| หลุม / เนิน | รูปร่างของ**ตัวพื้นเอง** | ฐานเฉพาะที่ (ตัดความลาดเอียงคลื่นยาวออก) |
| สิ่งกีดขวาง | **ของที่วางอยู่บน**พื้น | ระนาบพื้น (สูงจากพื้นเท่าไร) |

`detect_defects` จึงรับ `dev_plane_mm` เพิ่ม ใช้กับสิ่งกีดขวางอย่างเดียว ทั้งตอน
แบ่งก้อนและตอนรายงานความสูง หลังแก้: 350–353 mm ทุกเฟรม (sd 1 mm)

> **เทสต์ตัวนี้ใช้เฟรมจากกล้องจริง (`test/data/box_355mm.npz`) ไม่ใช่ตัวจำลอง**
> เพราะตัวจำลองสร้างอาการนี้ไม่ได้ — ลองแล้วถึงกล่องกว้าง 0.56 m ก็ยังได้
> `dev_local = dev_plane` เป๊ะ ฉากจำลองสะอาดเกินไป ของถูกมาร์คเป็น "ผู้ต้องสงสัย"
> ครบทั้งก้อน ฐานจึงมาจากพื้นล้วนตามที่ออกแบบไว้ ของจริงต่างตรงที่กล่องอยู่ริมเฟรม
> เห็นแค่ผิวบนบางส่วน และมีเงาบังอยู่ข้างหลัง เคยเขียนเทสต์เวอร์ชันจำลองไว้ก่อน
> แล้วพบว่ามัน **ผ่านทั้งที่ปิดการแก้ทิ้ง** จึงทิ้งไปแล้วเปลี่ยนมาใช้เฟรมจริง

> **ข้อจำกัดที่เจอระหว่างทาง:** ถ้าของกินพื้นที่เฟรมมากพอ (ในฉากจำลอง กล่อง
> รัศมี ≥ 0.14 m ที่กล้องสูง 0.90 m) RANSAC จะไป fit ระนาบบน**หลังกล่อง**แทนพื้น
> แล้วพื้นจริงกลายเป็นหลุมลึกทั้งผืน ยังไม่ได้แก้ — ในการใช้งานจริงพื้นกินเฟรม
> มากกว่าของเสมอจึงไม่เคยเจอ แต่ถ้าเอากล้องไปจ่อของใกล้ ๆ จะเจอ

## ผิวที่กล้องนี้วัดไม่ได้ (และระบบจะบอกเอง)

**ผิวเคลือบเงาแบบกระจก** (โต๊ะไม้ลงแลกเกอร์ อีพ็อกซีขัดเงามาก กระเบื้องโพลิช กระจก
ผิวน้ำ) — ลาย IR ที่กล้องยิงไปไม่กระเจิงกลับ แต่สะท้อนแบบกระจก สิ่งที่ stereo จับคู่ได้
จึงเป็น **เงาของเพดานในผิวนั้น** ไม่ใช่ตัวผิว

วัดจริงบนโต๊ะไม้เคลือบเงา (กล้อง 0.54 m):

| | ค่าที่วัดได้ |
|---|---|
| พิกเซลที่ได้ depth | 16% |
| ระยะที่รายงาน (p50 / p75 / p95) | 1.50 / 5.32 / 22.84 m |
| ไกลสุด | 65.5 m |
| ระยะจริงของผิวโต๊ะ | 0.5–1.2 m |

**ไม่มีค่ากล้องตัวไหนแก้ได้** — กวาดวัดแล้ว:

| ค่าที่ปรับ | ช่วงที่กวาด | fill ที่ได้ |
|---|---|---|
| `laser_power` | 0 → 360 | 10.5–11.0% (แบนราบ) |
| `auto_exposure_limit` | 4 ms → 200 ms | 10.5–10.7% (แบนราบ) |
| HDR | ปิด → เปิด | 5.6% → 10.9% (ดีขึ้นเท่าตัว แต่ยังไม่พอ) |

และแยกจาก "แค่แสงจ้า" ได้ชัด: ถ้าเป็นเรื่องค่าแสง พิกเซลสว่างต้องเสียมากกว่าพิกเซลมืด
แต่วัดแล้วเสียเท่ากันหมดทุกระดับความสว่าง (ได้ depth 14.5–19.6% ตั้งแต่มืดสุดถึงสว่างสุด)

ระบบจึงตรวจลายเซ็นนี้แล้วปฏิเสธตั้งแต่ต้น พร้อมบอกว่าเป็นเรื่องผิว ไม่ใช่เรื่องการเล็งกล้อง:

> ผิวสะท้อนแบบกระจก — ได้ค่า depth แค่ 16% ของภาพ และ 32% ของนั้นรายงานระยะเกิน 3.0 m
> (ไกลสุด 66 m) แปลว่ากล้องกำลังวัด "เงาสะท้อนของห้อง" ในผิวนั้น ไม่ใช่ตัวผิว ·
> ไม่มีค่ากล้องตัวไหนแก้ได้ ต้องเปลี่ยนผิว เช่น ปูกระดาษ/เทปด้าน หรือดับไฟที่สะท้อนอยู่เหนือผิว

**ผิวที่ใช้ได้ดี:** คอนกรีตขัดหยาบ อีพ็อกซีผิวด้าน พรม กระเบื้องยาง แผ่นโฟม —
ซึ่งครอบคลุมพื้นโกดัง/โรงงานเกือบทั้งหมดที่ AMR วิ่งจริง

### ตัวจำลองต้องไม่ "เก่งเกินกล้องจริง"

`synth` จำลอง noise ของ stereo แบบ **สัมพันธ์กันเชิงพื้นที่** (`noise_corr_px`
ค่าเริ่มต้น 7 px = หน้าต่าง block matching ของ D455) ไม่ใช่แบบอิสระต่อพิกเซล

ข้อนี้สำคัญกว่าที่คิด: ถ้า noise อิสระ การเฉลี่ยหลายพิกเซลจะลด error ตาม `1/√n`
เซลล์ที่มี 3–4 จุดจะดูแม่นมาก ทั้งที่กล้องจริงพ่นหลุมผีลึก 37 mm ตรงนั้น
เทียบเลขกันตรง ๆ (เฉลี่ยกี่ x กี่พิกเซล → sd ที่เหลือ):

| หน้าต่างเฉลี่ย | noise อิสระ (ไม่จริง) | สัมพันธ์กัน 7 px (ตรงกับกล้องจริง) |
|---|---|---|
| 3×3 | 0.33 | **0.87** |
| 5×5 | 0.20 | **0.77** |
| 9×9 | 0.11 | **0.58** |
